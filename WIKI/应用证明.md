## 一、系统基本情况

智能答辩分组编排系统面向研究生学位论文答辩的组织实施场景，用于替代人工在 Excel 中反复交叉核对的分组与排期工作。系统采用前后端分离架构：前端基于 Vue 3 + TypeScript + Vite + Element Plus，后端基于 Django 6 + Django REST Framework，数据存储采用 SQLite，生产环境由 waitress 提供服务，可通过 `scripts/build-exe.ps1` 打包为免安装的 Windows 单文件程序。

系统全部依赖以 `requirements.txt` 与 `package.json` 锁定版本，克隆源码后执行 `pip install -r requirements.txt` 与 `python main.py` 即可在浏览器中访问使用，具备完整可复现性。

## 二、主要功能

1. **基础数据管理**：教师（学院、职称、可担任角色、可参与答辩类型、校区偏好、不可用时间、回避关系）、学生（类型、导师、校区、答辩类型、指定秘书）、教室（校区、容量、可用时间）的增删改查与 Excel 批量导入。
2. **批量导入**：支持教师名单、学生名单、卡片式课表与整批资料的一次性导入，导入前提供校验预览，对缺年份、缺校区、重复学号等异常给出逐行提示。
3. **规则配置**：按预答辩、正式答辩、中期答辩分别配置每组学生人数（目标值/上下限）、评审人数、组长与秘书的最低职称、日期区间与排除日期、外院导师上限、导师回避开关及多项软约束权重。
4. **自动排期**：采用"人员先行"的三阶段求解（组长 → 评审与秘书 → 学生绑定），以整数规划完成组间人数、导师份额与教师出场次数的联合优化；硬约束（时间不可用、导师评审、专家资格、每组人数、外院导师上限、同一导师每组人数上限）全部显式建模，软约束按权重优化。
5. **两阶段联动**：正式答辩在预答辩结果基础上沿用组号、学生与秘书，重新轮换全部评审并回避本组导师，保证两阶段可比、可追溯。
6. **冲突检测与人工调整**：每次生成或调整后自动复核数据完整性、导师回避、专家重复、时间/容量冲突，逐条给出原因与处理建议；支持学生换组、更换专家/主席/秘书、调整时间与教室。
7. **结果输出**：导出 Excel 排期表（每组一表、导师与学生同色标注）与 Word 正式排版排期表、评审意见表。
8. **过程管理**：草稿校验后发布、历史版本快照与冻结、并发编辑保护、生成请求去重、服务端操作日志审计、数据库迁移前自动备份。

## 三、实际运行情况

系统在本单位真实答辩资料上完成了端到端试运行，主要结果如下（数据取自本机交付记录，未做人工修改）：

| 项目 | 实际结果 |
| --- | --- |
| 参评学生 | 301 人（原始资料 316 份，其中 15 人不参加本轮答辩） |
| 参与教师 | 111 位（含外院导师） |
| 校区 | 创新港、兴庆两个校区分别成组 |
| 预答辩 | 54 组，每组 3 位评审（含组长），每组学生 5～7 人 |
| 正式答辩 | 54 组，每组 5 位评审（含主席），沿用预答辩组号、学生与秘书 |
| 漏排 / 重复安排 | 0 人 |
| 单次自动排期耗时 | 约 1 分钟（优化前同一批资料约 2.5 分钟，且存在漏排） |
| 一致性校验 | 系统内置校验与独立硬约束核验结果一致 |

系统在生成结果中明确区分"已安排"与"未安排"：对确实无法满足全部硬约束的学生，逐人给出未安排原因（如外院导师数量、每组人数下限、单组导师席位上限、时间与专家资格），不静默丢弃学生，便于组织者补充资料或调整规则后重排。

## 四、应用效果

1. **效率提升**：原需数人日完成的 300 人规模分组与排期，现由系统在分钟级完成，且可反复重算比对。
2. **质量可控**：每组人数、导师份额、教师出场次数、外院导师比例、导师回避等要求由模型统一保证，避免人工排表常见的漏排、重复与自导自审。
3. **过程可追溯**：每次生成、调整、发布均留存版本快照与操作日志，出现问题可定位到具体版本与操作人。
4. **交付规范**：排期结果可直接导出为 Excel 与 Word 文档，格式满足学院归档与公示要求。

## 五、结论

经实际部署与真实资料试运行，智能答辩分组编排系统功能完整、运行稳定，能够满足学位论文答辩分组与排期的业务要求，已在相应工作中实际应用，效果良好。

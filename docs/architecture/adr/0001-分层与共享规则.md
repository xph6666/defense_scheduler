# ADR-0001：保留分层入口与共享业务规则

- 状态：记录现有设计，本轮整理继续采用。
- 日期：2026-10-09。
- 来源：[V2 架构说明](../架构升级说明.md)。

## 背景

项目同时提供 Vue 页面、Django 接口和 Windows EXE。政策转换、生成、调整、发布与导出必须遵守同一套规则。新人并行开发需要识别服务、算法和运行入口的边界。

## 决定

- 保留 `src/`、`api/`、`defense_scheduler/`、`algorithm.py`、`scheduling/` 和现有启动／打包入口的位置。
- 新增用例编排优先进入应用服务，领域规则保持不依赖 Django ORM。
- 政策默认和导师配色继续使用 `shared/`，前后端共同读取并用测试核对。
- 排期写操作遵守既有事务、revision、冻结和审计保护；修改一致性方案另立决策。
- 本轮按用途整理文档和样例，保留被运行或本地测试依赖的路径。

## 后果

新成员可以沿现有边界工作，文档整理对启动和打包的影响较小。算法入口和部分 HTTP 编排仍较集中，后续拆分需要逐用例验证；文档约定仍需评审和测试配合执行。

## 已考虑的替代方案

一次性重排所有源码和测试目录会同时影响导入、脚本、资源与 EXE，当前收益不足以覆盖验证成本。每端独立维护政策容易产生默认值和验收语义差异。

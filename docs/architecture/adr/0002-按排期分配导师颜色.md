# ADR 0002：按排期的完整导师集合分配颜色

日期：2026-10-26。状态：本地实现与自动验证通过，待正常评审合并。

## 背景

仅以姓名哈希对 64 色取模，不能满足 PRD-040 的同份排期导师颜色互异要求。`导师001` 与 `导师023` 的首选槽位均为 37；增加固定色板仍不能消除哈希碰撞。网页按筛选后的子集分配又会导致相同版本的颜色漂移。

## 决定

使用所选版本所有分组中的导师姓名集合，去空白、去重后按 UTF-16 码元顺序排序。Python 哈希也按 UTF-16 码元截断为 32 位，保持扩展汉字和表情与 JavaScript 一致。

优先保留原哈希槽位；碰撞时使用共享配置 `collisionStep=17` 查找空槽，并在色板长度改变时调整到互素步长。跳过相邻近似色，减少碰撞示例中难以辨认的差别。超过色板后使用一致的整数公式生成浅色／深色对，并跳过已用颜色；超过独立颜色容量时明确报错。

网页先用全部分组分配，再筛选日期、校区或问题分组；卡片、表格和打印使用该集合。Word／Excel 从所选版本的导出对象或冻结快照取得相同集合。浅色用于网页和 PDF 底色，深色用于文档字体，同一槽位保持师生对应。

不新增颜色数据库字段，不修改既有人员关系或冻结快照，也不把当前全部教师加入历史版本的颜色集合。其他排期可复用色值，不承诺不同排期永远给同一导师保留相同颜色。

## 影响与验证

已有无碰撞姓名尽量沿用首选色；存在碰撞的旧排期会重新避让，导出色值可能变化。冻结姓名集合稳定时，重新导出不受当前资料改名、筛选或输入顺序影响。

后端和前端分别验证碰撞姓名、超过 64 位、顺序反转和扩展字符；另比较 166 个姓名的两端完整色对。真实导出对象检查 Word／Excel 的导师和学生同色，前端检查跨组导师在 PDF 中同色。自动检查不替代最终实际版式与打印验收。

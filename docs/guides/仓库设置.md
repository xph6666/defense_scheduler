# GitHub 仓库协作设置

仓库：[xph6666/defense_scheduler](https://github.com/xph6666/defense_scheduler)。以下设置由拥有仓库管理权限的成员执行，设置完成后更新 [STATUS.md](../../STATUS.md) 的 GOV-004。

## 成员与评审

确认五人的 GitHub 账号和模块主责，授予所需仓库权限。日常开发通过个人分支和 PR，至少一名其他成员审批；关键规则、权限、模型和事务改动由相关模块负责人参与。

本轮没有提供完整人员账号，不生成虚假的 CODEOWNERS。确认实名后可按 `src/`、`api/`、`scheduling/`、`shared/`、`scripts/` 等路径登记负责人；只有配合保护规则时才能形成强制评审。

## 主分支保护

在仓库 Settings 的 Rulesets 或 Branches 中为 `main` 设置：

- 要求通过 Pull Request 合并，至少一名其他成员批准。
- 要求解决评审讨论；新代码推送后重新检查受影响的审批。
- 要求 `documents`、`frontend`、`backend` 三项状态检查成功，并在合并前同步目标分支。
- 禁止强制推送和删除主分支，明确管理员的例外处理及记录方式。

先让本轮工作流实际运行一次，再选择对应检查名称。保存后用小 PR 核实审批和检查是否确实阻止未满足条件的合并。

官方参考：[受保护分支](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches)。

## 完成记录

在 GOV-004 回填配置人、日期和验证 PR。当前整理账号具备 push 权限，缺少 admin 权限，保护规则需要管理员另外执行；这项状态与代码推送、工作流执行分别记录。

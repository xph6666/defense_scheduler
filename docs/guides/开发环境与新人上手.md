# 开发环境与新人上手

先阅读 [STATUS.md](../../STATUS.md) 和 [CONTRIBUTING.md](../../CONTRIBUTING.md)。以下命令在项目根目录的 PowerShell 执行；macOS／Linux 使用 `.venv/bin/python` 替代 Windows 虚拟环境路径。

## 1. 安装与本地配置

使用 [.nvmrc](../../.nvmrc) 中的 Node.js 版本和 [.python-version](../../.python-version) 中的 Python 版本系列。当前为 Node.js 24.13.1、Python 3.12；依赖分别由 `package-lock.json` 和 `requirements.txt` 固定。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
Copy-Item .env.example .env
```

已有 `.env` 时保留自己的配置，避免覆盖。首次复制后编辑：

```env
VITE_USE_MOCK=false
VITE_ENABLE_DEMO_TOOLS=false
VITE_API_BASE_URL=/api
VITE_API_PROXY_TARGET=http://localhost:8000
DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,testserver
DJANGO_CORS_ALLOWED_ORIGINS=http://localhost:5173
```

配置示例用于本地开发，生产配置使用 `.env.production.example` 和运维说明。每人使用自己的本地数据库，团队联调与自动化测试使用独立测试库。

## 2. 开发启动

终端一启动后端：

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

终端二启动前端：

```powershell
npm run dev
```

访问终端显示的 Vite 地址；`/api` 代理到后端。账号来自自己的 Django 数据库。首次导入样例见 [tests/fixtures](../../tests/fixtures/README.md)。

源码一体化运行可先 `npm run build`，再运行 `.\.venv\Scripts\python.exe main.py`。它默认使用 `app-data` 运行数据，可能与 `manage.py` 的根目录数据库不同，排查时先确认实际库路径。

## 3. 首次自检

1. 登录真实后端，查看教师、学生和教室页面。
2. 导入合成样例，确认规则，生成草稿并检查冲突提示；根据资源情况修正后再发布。
3. 检查刷新、历史版本和导出，确认操作确实走 API。
4. 执行[日常验证命令](测试与发布.md)，记录结果。
5. 在 `STATUS.md` 认领一个小任务，创建分支，提交 PR，由同伴评审。

可选浏览器验证工具：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m playwright install chromium
```

## 4. 常见排查

- 无法登录：确认访问的后端、数据库和账号；管理员初始凭据仅保存在本地。
- 看见演示数据：确认 `VITE_USE_MOCK=false`，配置修改后重启 Vite。
- 接口 401：重新登录；接口 403：检查账号角色；排期 409／428：刷新版本，带正确 revision。
- 构建失败：先核对 Node 版本和锁文件，使用 `npm ci`；勿在安装失败时随意升级依赖。
- 命令提示 `npm.ps1` 执行策略：可使用 `npm.cmd`；也可按测试文档直接调用 Node 入口，无需更改系统执行策略。

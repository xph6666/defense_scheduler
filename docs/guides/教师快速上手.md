# 答辩安排助手：第一次使用

更新日期：2026-10-29。当前预／正式答辩使用联合生成、3/5 人专家配置和全局三阶段排期，详见[算法与规则](../architecture/三阶段排期算法与优化.md)。旧的本批 301 人操作记录仅用于对应历史版本。

登录后，在工作台点击 **开始一次答辩安排 →**。第一次使用推荐跟着五步向导操作；熟练后可以直接使用左侧的完整管理功能。

## 1. 选择答辩类型

选择预答辩、正式答辩或中期答辩，点击 **下一步：准备资料 →**。进入向导不会清空资料或自动重新生成安排。

## 2. 准备资料

向导会显示学生、教师与专家、教室的已有数量，并告诉您还缺哪份资料。

- 已有名单：点击“导入学生”“导入教师”或“导入教室”，选择 Excel 或 CSV 文件，点击“检查并预览”，核对后再“确认导入”。预览不保存资料。
- 只有少量资料：点击“查看 / 新增 / 修改”，进入管理页后点击“新增”。补充完点击“资料已补充，返回向导”。
- 已经录入过：直接核对和补充，不需要重新导入。
- 学生：重点确认导师、校区、参加的答辩环节。
- 教师：重点确认职称、角色、可参加的环节、可用窗口及不可用时间；空白且未确认时可生成草稿，按无额外限制计算并保留待核对提醒；已知课表仍生效。没有任何限制时可明确开启“可用时间已确认”；课表导入仍在教师管理页。
- 指定秘书：在教师角色中标记“秘书”。已指定人员以名单资格为准，不因助理教授、博士后、工程师等职称被排除；仍检查停用、课程和时间冲突，以及不能给自己的学生担任秘书。未明确角色的历史资料才使用备用职称门槛。
- 指定组长／主席也能担任普通专家；在教师资料关闭“适合担任组员”后，该教师才会被排除出普通专家席位。导入预览与教师列表会显示这项资格，停用和时间冲突仍会阻止分配；不会因此获得秘书资格。名单外补入的外院导师仍仅能任普通专家。
- 教室：预／正式答辩先不需要准备教室，人员时间表确定后再预约；中期按原流程准备。

“已有资料”只表示有记录，后续生成时还会检查是否符合安排要求。学生、教师资料核对后，点击 **资料已核对，确认要求 →**。

导入时可对照原表行号、原始时间和识别后的时间检查。教室借用单支持卡片式记录、日期范围及节次范围，例如第 1～8 节会按节次表拆成上午和下午，午间不自动计为可用。日期范围按每天相同的时段展开，最长 366 天。多个工作表可在预览后切换，修改选项后需要重新检查。

文件缺少校区时，请选择“文件未注明时使用的校区”；缺少年份时，可填写“缺少年份时补全为”。已有年份不会被覆盖，也不会自动改为今年。无法识别的日期、时间会指出需修正的行和字段，并阻止整批导入。课表仍需单独提供该学期第一教学周的周一，不能用答辩开始日期代替。

### 批量导入学生和导师

学生、教师和教室管理页各使用一个搜索框，可直接输入姓名、学号、导师、学院、职称、校区等对应资料关键词；多个词用空格分隔，清空搜索框后恢复全部结果。学生页的“分组显示”只选择展示哪一环节的分组，不修改学生参与环节。

学生已导入却显示本次人数为 0 时，先核对当前选的是预答辩、正式答辩还是中期答辩。页面会显示“已录入总人数／参加本环节人数”，并提供切换入口，无需重复导入。例如全部学生只参加正式答辩时，预答辩人数应为 0；应切换到正式答辩查看。

明确不参加本次答辩者会单列显示，不属于漏填参与环节；不得通过补校区或批量添加环节重新纳入。

确实漏填参与环节时，在学生页勾选学生，点击“设置参与环节”，核对后确认补充；也可使用未设置环节提示中的批量入口。操作只添加环节，保留已选环节和其他资料。普通学生导入增加“文件未注明参与环节时补充为”，默认当前环节，检查时请确认；原表已有环节保持原值。

同时有软件学院教师名单和学生名册时，可先进入“教师/专家管理”或“学生管理”，点击 **批量导入学生与导师**：

1. 选择一份软件学院名单（含指定组长、秘书），再多选学生名册，最多 10 份。
2. 明确选择本批学生参加的答辩环节，点击 **检查批量资料**。多个工作表可切换后重新检查。
3. 核对教师身份、角色、参排名单、不参排名单及原始备注。仅参排学生缺失校区可在“学生”预览逐行选择，或统一补充原表空白校区；修改后重新检查。
4. 检查通过后点击 **确认批量导入**。有错误时整批不保存；同学号相同资料会合并，资料冲突必须先核对。

参排学生名单外的导师也会补入教师库，缺失职称显示“外院导师（职称待确认）”，不推测为教授或副教授。已有真实职称保留。这批外院导师仅能担任普通专家，不能安排为组长、主席或秘书；软件学院名单中明确指定的角色保留。系统按姓名关联教师，同名不同人须先整理身份资料。

每份文件不超过 5 MB，本批合计不超过 20 MB；每个工作表不超过 1000 行，本批学生合计不超过 3000 行。以上操作维护公共资料，确认前请核对更新内容。

## 3. 确认日期和人数

按页面提示确认本次要求：

1. 核对当前答辩类型。
2. 设置开始日期、结束日期和每组学生、专家人数。
3. 需要修改人数上下限、导师回避、职称要求或分组偏好时，展开“更多要求”。收起设置不会改变已保存的值。
4. 点击 **保存要求，去生成草稿 →**。只有保存成功，才会进入下一步。填写不符合要求时，页面会指出需修改的内容；未保存时返回上一步会保留当前填写，离开向导前会提示。

## 4. 生成并核对草稿

预／正式答辩点击 **联合生成预答辩与正式答辩**，核对两个阶段日期。正式开始日期必须晚于预答辩结束日期。预答辩默认 3 位专家，可选 5 位；正式阶段沿用原学生组和人员，只补本院专家至 5 位，组长计入专家总数，秘书另计。

系统先安排所有组长及时间，再补齐专家与秘书，最后分配具体学生并调整集中到场。通常每位导师每场 2 名学生，3 位导师合组通常共 6 人；5 名学生可排 2+3，减少尾生单独到场。明确允许多人同组时在教师资料设置，并检查整组人数上限。正式阶段按原班人员寻找共同可用时间，不另行拆组换人；缺资源则列明原因。中期仍使用独立生成入口与原场景人数。

- 出现问题：查看“冲突检测”的原因和建议。
- 查看“未安排学生”及具体原因。搜索上限提示表示本次未找到完整方案，不代表所有可能方案均无解；补充时间、教师资格或调整日期后再生成。
- 展开教师工作量统计，核对指导学生数、参与组数和到场时段；上午下午覆盖不满足时查看软目标提示。
- 向导默认按日期显示日程，可筛选日期、校区，或只看有问题的分组。卡片和表格视图仍可切换使用。
- 查看名单：展开“查看教师与学生名单”。
- 修改人员、时间或教室：点击对应分组的“调整本组”；卡片/表格视图中点击“调整”。
- 学生换组：点击“移动学生”。
- 重新检测或刷新：点击“更多操作”；冲突检测面板也可重新检测。
- 需要查看分组质量评分：展开“查看分组质量评分”。

核对后，点击底部 **已核对，去发布与导出 →**。

## 5. 发布和导出

核对无误后点击 **校验并发布**，再点击 **导出 Excel/Word/PDF**，选择文件格式并下载。

- Word 适合查看和发送时间安排；Excel 适合进一步整理分组明细。
- 没有硬冲突的草稿也可以导出，文件会标注草稿状态；有硬冲突时先处理并复核。切换历史版本时等待加载完成，再导出对应版本。
- 发布后内容锁定。预／正式需要重新安排时使用同一个联合入口，历史版本仍可从“排期版本”下拉框查看和导出。

任何页面右上角都有 **使用帮助**。向导底部有“上一步”和“下一步”；刷新页面会保留当前步骤并读取已保存的数据。只读账号可以查看和导出已发布安排；资料维护、生成和发布需要管理员操作。

快速查看和双击操作见[本批资料操作入口](本批资料操作入口-2026-10-23.md)。

## 历史流程：2026-10-23 本批资料（policy 2）

以下保留当时真实资料的来源和操作过程，不作为 policy 3 的人数、教室前置或本轮验收依据。新版请按上文联合生成流程和[最新验证范围](../releases/三阶段算法优化-2026-10-29.md)操作。

本节针对 `test-data/排答辩文档` 和 `test-data/26年数据` 中的本批 316 人资料。操作顺序为：启动当前源码 → 联合导入名单 → 核对301人参排和15人不参排 → 导入课表 → 准备教室资源 → 分别保存两阶段要求 → 联合生成 → 核对 → 分别发布和导出。原文件保留不改；点击确认导入会更新当前运行系统的数据库。此前验收使用隔离库，其结果不会自动出现在日常业务库。

### 1. 启动当前版本

本轮新增功能在本地源码中，尚未重新打包 EXE。使用当前项目启动；已有资料时，先关闭程序并备份整个 `app-data` 文件夹。

在当前项目目录的 PowerShell 中，使用现有 `.venv` 环境：

```powershell
Set-Location 'D:\项目\智能答辩分组编排系统'
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:VITE_USE_MOCK = 'false'
$env:VITE_ENABLE_DEMO_TOOLS = 'false'
npm run build
.\.venv\Scripts\python.exe main.py
```

首次安装先用 `python -m venv .venv` 创建环境，并用 `npm ci` 安装前端依赖；完整环境步骤见[开发环境与新人上手](开发环境与新人上手.md)。通常访问 `http://127.0.0.1:8000`，以终端实际地址为准。已有库使用原管理员账号；首次空库账号见 `app-data/INITIAL_ADMIN.txt`。保持启动终端开启。

### 2. 准备本次输入

以下路径均相对项目的 `test-data` 目录：

| 文件 | 用途与入口 |

| `排答辩文档/指定组长秘书.xlsx` | 联合导入中的软件学院教师名单，识别指定组长、秘书及原职称 |
| `排答辩文档/23级答辩地点统计-含学生信息-导师信息-答辩地点.xlsx` | 联合导入中的学生名册，原表316人，本次301人参排、15人不参排 |
| `26年数据/2025—2026学年第二学期软件学院课表(1).xlsx` | 教师管理的“导入课表” |
| `排答辩文档/学部课表.xls` | 教师管理的“导入课表” |
| `26年数据/学部课表.xls` | 教师管理的“导入课表” |
| `26年数据/学院研究生课表系统导出.xls` | 教师管理的“导入课表” |

历史 302 人已统计名单及预／正式答辩 Word 用于最后对照，不与本次 316 人名册混作新增学生。原借用单可辅助准备教室，但其日期必须覆盖相应答辩阶段，不能将仅覆盖 4 月的借用记录当成 5 月的可用依据。

### 3. 联合导入学生和导师

1. 左侧“基础数据 → 学生管理”，点击“批量导入学生与导师”。教师管理也有同一入口。
2. “选择软件学院名单”选择 `指定组长秘书.xlsx`；“选择学生名册”选择上述 316 人原表。
3. “本批学生参加的答辩环节”同时勾选“预答辩”和“正式答辩”。本次不要勾选中期。
4. 空白校区补充选项保持空白，点击“检查批量资料”。
5. 在“不参加本次答辩”预览核对15人及原表原因：10人转博、2人休学、2人外院答辩、1人已毕业。不为这些学生补校区。只有其他参排学生缺校区且无明确原因时，才需要核对补充。
6. 若修正校区、切换工作表或替换文件，重新点击“检查批量资料”。
7. 核对预览：301人参排、15人不参排、软件学院教师43人、参排学生所需外院导师68人，共111位教师；无阻断错误后点击“确认批量导入”。相同学号的已有记录会更新，这15人的错误参与环节会清空，原始备注及空白校区保留。

在教师管理核对：16位指定组长可任组长／主席及普通专家；标记“不适合组员”的教师关闭“适合担任组员”。11位指定秘书按名单具备资格，无需将其职称改成讲师或教授。名单外导师为“仅普通专家”，未知职称显示“外院导师（职称待确认）”。教师应在用，可参加两个阶段；空的教师参与类型保留不限类型的历史语义。

学生管理应显示总资料316人、当前预答辩或正式答辩301人，以及明确不参排15人。明确不参排者不计入“未设置参与环节”，也不会被一键补充环节重新加入。“分组显示”不会改变参与环节。

### 4. 导入四份课表

完成教师导入后，在“教师/专家管理 → 导入课表”，逐份选择上述四份课表，每份的“学期第一周周一”都填 **2026-03-02**，再点击“导入课表”。每次完成后核对结果和警告，再换下一份文件。

这四份实际都是春季课表，包括 9 月导出的文件；不能按文件导出日期选择秋季第一周。用户确认的秋季第一周周一 2026-09-14，仅用于另一次真正的秋季课表。课表导入将上课时段追加为已有教师的不可用时间，重复记录会去重。出现“教师不在系统中”时，先判断是否为本批学生导师；相关导师应先补入再重导，课表中其他无关教师无需全部加入本批评审。

教师临时请假、不宜同组等信息在教师管理补充。出现无法识别的时间先核对来源，不能通过清空不可用时间来绕过检查。

### 5. 先准备人员排期所用的教室资源

人员优先核对，实际房间号可以后补。无教室时后端会保留人员草案，但不能形成可发布的完整时间安排；当前没有单独的人员分组页面。

为走完整流程，可在“教室管理 → 新增教室”先录入明确标为待定的资源；本轮验收使用如下配置：

| 校区 | 资源数量 | 名称示例 | 容量 | 可用时间 |
| --- | --- | --- | --- | --- |
| 创新港 | 4 间 | `待定教室-创新港-1` 至 `4` | 每间 40 | `周一至周五全天` |
| 兴庆 | 4 间 | `待定教室-兴庆-1` 至 `4` | 每间 40 | `周一至周五全天` |

这些是排期资源占位，不能当作真实借用确认。已有教室直接核对，不重复新增同名资源。对外发布实际通知前，落实真实教室并按真实可用时段重新检测。

### 6. 分别保存两个阶段的安排要求

进入左侧“安排要求”。每一阶段可先“恢复默认”，再填下表；每个页签修改后分别点击“仅保存要求”，不要只改其中一阶段。展开“更多要求 · 人数范围、角色资格与分组偏好”查看人数边界和课程／衔接开关。

| 项目 | 预答辩 | 正式答辩 |
| --- | --- | --- |
| 排期开始、结束日期 | 2026-04-01～2026-04-15 | 2026-05-06～2026-05-22 |
| 每组学生人数 | 目标 6，最少 4，最多 8 | 目标 6，最少 4，最多 8 |
| 专家总人数 | 固定 5，含组长 | 固定 5，含主席 |
| 秘书人数 | 1，另计 | 1，另计 |
| 导师规则 | 导师与学生同组 | 开启导师回避；导师在同一时段的其他组评审 |
| 组长／主席最低职称 | 副教授及以上 | 教授／研究员等正高 |
| 有课半天不排 | 开启 | 开启 |
| 软件学院专家至少 | 按本阶段默认要求 | 3 位，包含主席 |
| 沿用预答辩分组 | — | 开启 |
| 避开周末、避开节假日 | 开启；指定排除 4 月 4、5、6 日 | 开启；按本次实际排除日期填写 |

表中日期用于复跑这批春季资料，不是新一轮实际答辩日期的确认。实际安排换日期时，课表、请假和教室可用范围也需对应。

软约束先保留恢复默认后的值，优先把硬冲突降为 0。不要为了凑历史组数减少评审或漏掉学生。外院导师的学生分组阈值按校区分别检查：少于 3 人为 1 组，3 人及以上为 2 组；由系统执行。

### 7. 使用联合生成

1. 进入左侧“分组与发布”，当前类型选择预答辩或正式答辩。
2. 点击“联合生成预答辩与正式答辩”。
3. 弹窗核对两个阶段各自日期、目标人数及 5 位评审，点击“确认联合生成”。
4. 系统先分别预检两阶段资料。缺导师、学生未选择环节等错误要回到基础数据修正，再重新打开生成弹窗；预检通过后自动继续生成。
5. 等待两阶段草稿返回。全量组合搜索可能需要数分钟，网页生成请求的等待上限为 10 分钟；不要连续重复点击。若请求超时，按原配置重试可获取同一请求结果。

联合生成会新建两份草稿、重新分配本轮秘书，并让正式答辩沿用本轮预答辩的学生分组和秘书。只单独点击“生成排期草稿”，不能替代这个完整的两阶段衔接过程。

### 8. 逐阶段核对、发布、导出

在左侧切换“当前答辩类型”，分别查看两份草稿；“排期版本”下拉框确认当前查看的是本轮新版本。

核对清单：

- 两阶段各自覆盖301位参排学生，每人只出现一次，15位不参排者均不出现；组内学生 4～8 人。
- 每组 5 位评审（含组长／主席），另有 1 位秘书，角色不重复；秘书不能指导本组学生。
- 预答辩导师同组；正式答辩导师回避自己的学生，但在同一场次的其他组参加评审。“同场”是相同时段，不只是同一天。
- 正式每组至少 3 位软件学院教师；外院导师仅专家；组长普通专家资格保留，不适合组员者除外。
- 人员、课程、教室和时间无硬冲突；两阶段学生组与秘书保持一致。
- 同日跨校区和工作量均衡提示人工检查，确认交通时间及工作量可以接受。

有问题时用“调整本组／调整”“移动学生”修正，再在“冲突检测”重新检测。调整预答辩学生或秘书后，必须复核正式答辩的衔接；需要整体重排时重新联合生成。

确认真实地点并且硬冲突为 0 后，分别点击“校验并发布”，再点“导出 Excel/Word/PDF”，本流程重点核对 Excel 和 Word。最终保存四份文件：预答辩 Excel、预答辩 Word、正式答辩 Excel、正式答辩 Word。检查每份均为本轮版本、完整301位参排学生；已发布版本需要修改时，新建草稿再校验和发布。

本次参排名单以用户澄清后的原表备注为准，不以历史302人名单的差额决定加入或剔除。更正后的固定参数复跑得到两阶段各301人、50组，系统和独立核验均无硬冲突，学生组及秘书保持一致。网页不提供相同种子的输入框，验收应核对参排覆盖及业务规则，不要求每次生成完全相同的组别和日期。

此前316人全量参排的报告仅为历史过程，不能继续作为当前结果。更正后的结果、资源假设和核验限制见[301人排期结果交付](../releases/排期结果交付-2026-10-23.md)。原文件和日常业务库保持原样，通过交付目录的独立启动入口查看修正版草稿。

本流程说明不包含真实姓名、学号和私人导出。`test-data` 的原始资料、隔离数据库和排期文件继续只保留本地，不提交 Git。

## 使用新版程序

- 第一次使用：把 `DefenseScheduler.exe` 放在固定文件夹中，双击启动。首次账号信息保存在同目录下的 `app-data/INITIAL_ADMIN.txt`，登录后请修改密码。

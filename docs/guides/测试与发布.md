# 测试与发布

日常开发规则见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。工作流定义为 [.github/workflows/ci.yml](../../.github/workflows/ci.yml)，执行结果关联 GitHub 提交。

当前三名开发共同修改，两名测试分别独立进行全系统、全流程测试，见[团队职责与任务协作](团队职责与任务协作.md)。**每位测试用完整真实数据跑通适用场景是最终验收的必要条件**。两人各自记录全部测试结果，共用问题清单；按[真实数据全流程测试与验收](真实数据全流程测试与验收.md)检查功能正确性、实际操作是否顺畅及交付产物。不能将两人各测一部分拼成通过，小样本、合成数据、跳过项和测试教室条件下的成功也不能替代全部实际业务场景验收。

## 日常检查

项目根目录，PowerShell：

```powershell
.\.venv\Scripts\python.exe scripts/check-project-docs.py
npm run lint
npm run test:domain
npm run build

New-Item -ItemType Directory -Path .tmp -Force | Out-Null
$env:DJANGO_DB_PATH = Join-Path (Get-Location) '.tmp/verification.sqlite3'
$env:DJANGO_SECRET_KEY = 'local-isolated-verification-only'
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test api defense_scheduler --noinput
git diff --check
```

这些环境变量用于当前测试终端，结束后关闭终端或恢复自己的配置。Django 测试框架创建独立测试数据库，禁止把测试指向真实业务库。

`npm run build` 包含 Vue／TypeScript 检查。若 npm 的 PowerShell 包装器受限制，可用 `npm.cmd`，或直接调用现有本地入口：

```powershell
node scripts/test-frontend-domain.cjs
node node_modules/eslint/bin/eslint.js . --ext .ts,.vue
node node_modules/vue-tsc/bin/vue-tsc.js -b
node node_modules/vite/bin/vite.js build
```

## CI 范围

| 检查名 | 内容 |
| --- | --- |
| `documents` | 文档本地文件与锚点引用、主入口和样例、提交空白检查 |
| `frontend` | `npm ci`、lint、领域测试、关闭 Mock／演示工具的正式构建 |
| `backend` | 固定 Python 版本系列、安装运行依赖、系统检查、迁移一致性、后端回归 |

PR、推送 `main`／`feat/**`／`fix/**`／`docs/**`／`chore/**` 和手动触发均运行。后端暂以 Windows + SQLite 为 CI 基线，前端与文档使用 Linux。工作流中的 Actions 固定到经核实的官方提交；运行版本读取根目录版本文件。

`api/tests.py` 有依赖本地 `排答辩文档/` 的可选真实资料测试，远程没有这些资料时会跳过。基础回归使用仓库内合成输入；跳过的真实资料测试不能宣称已由 CI 覆盖。浏览器、EXE、存量业务库升级和 PostgreSQL 不是本轮 PR 工作流的验证范围。

## 按风险补充验证

- 页面或跨端行为：正式构建后运行 `python scripts/test-v2-ui.py --run`，使用临时库和 Playwright。
- 导入日期、预览或秘书资格：运行 `python manage.py test api.test_import_dates api.test_import_warnings api.test_designated_secretary --noinput`；正式构建后运行 `python scripts/test-import-ui.py --run`，使用合成上传文件和临时库检查预览无写入、确认导入、参数变更失效、错误阻止与窄屏显示。需要已安装 Playwright 及 Chromium。
- 迁移变化：空库和存量副本分别验证，检查关系、历史快照与回退步骤。
- 联合批量导入：`python manage.py test api.test_cohort_import --noinput`；正式构建后运行 `python scripts/test-cohort-ui.py --run`，使用临时库和合成文件检查多文件、明确答辩环节、预览无写入、校区修正后重验、原子确认、导师关系、外院角色限制和窄屏。默认端口 8794，可用 `COHORT_UI_PORT` 调整。
- 单搜索框与资料状态：`python manage.py test api.test_student_participation --noinput`、`npm run test:domain`；正式构建后运行 `python scripts/test-materials-ui.py --run`，使用临时库复现仅有正式学生而选择预答辩的情形，检查总数／本次人数、切换入口、单框跨字段搜索、普通导入环节、批量补设与窄屏。默认端口 8795，可用 `MATERIALS_UI_PORT` 调整。
- 本轮人数与教师字段迁移：`python scripts/test-integration-upgrade.py` 新建合成旧库，验证 0009→0010→0011、预答辩固定 5 位、旧教师 `expert_only=false` 及角色／导师关系／其他设置／已发布快照保留；真实业务库升级仍须先备份并单独验收。
- 算法优化：固定输入规模和场景，验证硬约束、资源不足、耗时和软目标。
- 两阶段全量算法：安装 `requirements.txt` 中含 SciPy 的依赖后，执行 `python manage.py test api.test_algorithm_v2 --noinput`。当前真实批次按301位参排、15位不参排检查，见[修正版交付](../releases/排期结果交付-2026-10-23.md)及[操作入口](本批资料操作入口-2026-10-23.md)。真实资料仅在隔离库运行，不进入共享测试或CI；此前316人全部参排的记录不作为当前验收依据。
- 不参排处理：`python manage.py test api.test_cohort_import api.test_student_participation --noinput`、`npm run test:domain`；浏览器用 `python scripts/test-cohort-ui.py --run` 验证明确备注优先、不参排名单及原始原因、旧环节清空、不误报未设置环节、批量补设拦截，并确认模糊备注或单纯空白校区不会被自动排除。
- 导出变化：检查所选版本、备注、成员计数、配色以及 Word／Excel／PDF 版式。
- 打包变化：执行 `scripts/build-exe.ps1 -ReleaseName <新版本名>` 后，用 `scripts/test-exe-v2.py --exe release/<新版本名>/DefenseScheduler.exe` 核验实际 EXE。构建会安装 `requirements-build.txt` 并实跑 SciPy MILP；EXE 验证还需 `requirements-dev.txt` 中的 psutil。输出及中间目录已存在时拒绝覆盖，省略版本名则生成带时间戳目录。当前程序验证见[2026-10-26 EXE 构建记录](../releases/EXE构建与上传限制修复-2026-10-26.md)。

仅改变文档与 CI 时执行对应检查，并对新流水线使用的现有命令做一次完整基线验证。通过后只有新改动或新失败才需要重复相应检查。

## 发布清单

1. 确认迭代范围、未实现部分、关联任务和验收结果，更新发布说明。
   两名测试各自在同一交付候选版本完成全系统、全流程测试和完整真实数据验收，分别记录测试人、输入、配置、实际结果、限制及证据；失败、阻塞及未执行项不能登记为已验收。
2. 主线 CI 通过；按本次风险执行浏览器、升级副本与导出验证。
3. 生产构建关闭 Mock 和演示工具，检查配置与打包资源。
4. 发布 EXE 时重新打包并测试实际产物，不能用源码通过替代 EXE 验证。
5. 生成校验摘要，核对压缩包不含业务库、密钥、账号文件或真实输入资料。
6. 项目协调人与相关负责人确认后创建版本标签、上传发布物，记录回退与备份方法。
7. 回填 `STATUS.md` 的版本、任务和验证链接。

验证记录至少包含日期、代码版本／PR、运行环境、命令、结果、跳过项和限制。不能把工作流存在写成远程运行通过，不能把历史验证写成当前验证。

最新导入修复及真实流程汇总见[2026-10-17 验证记录](../releases/导入修复与流程验证-2026-10-17.md)。真实输入及其逐行报告、截图和导出保持在忽略目录 `test-data/`；共享文档只记录汇总结论，不提交真实资料。小规模流程通过不能替代三类全量排期验收。

三份业务分支的来源、冲突处理与最新合成回归见[2026-10-19 集成记录](../releases/分支集成与验证-2026-10-19.md)。10 月 17 日真实资料记录保留历史结果，不与本轮合成回归混写。

## 本地发布产物保留规则

联合批量导入的功能及真实文件预览汇总见[2026-10-20 验证记录](../releases/批量导入与外院导师-2026-10-20.md)。逐行校区缺口报告保留在本地忽略目录，不提交原始名单或诊断库。

- `release/` 保留最新已验证版本目录、对应 ZIP、校验摘要和产物清单。2026-10-26 Windows 构建位于 `release/v2026.10.26/DefenseScheduler.exe`；脚本默认输出到带时间戳的新版本目录，保留旧程序和数据。实际 EXE 合成回归与完整真实业务验收分别记录。
- 开发中的候选版本单独命名，注明日期和验证状态。新版验收后清理被替代的旧程序、重复压缩包及构建中间产物；只有实际需要回退时才额外保留一个旧版本。
- 删除旧发布目录前，先检查其中的 `app-data/`、数据库、密钥、账号文件和独有导出结果，将需要保留的内容保存到 `backups/`，验证副本后再删除程序。发布包不得混入这些本地数据。
- `build/` 可在无构建任务运行时清理。`.tmp/` 中完成验证后不再使用的临时虚拟环境和 EXE 副本可清理；文档引用的验证证据和历史备份继续保留。
- `.venv/`、`node_modules/`、当前 `dist/`、运行依赖、源码、需求、测试样例和真实资料按实际用途维护。文件日期较早不代表已经过时。

本地清理记录保存在 `backups/local-cleanup-日期/cleanup-manifest.json`，记录删除范围、数据副本及校验摘要。这些产物与记录遵循 `.gitignore`，不提交业务数据。

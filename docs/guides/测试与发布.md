# 测试与发布

日常开发规则见 [CONTRIBUTING.md](../../CONTRIBUTING.md)。工作流定义为 [.github/workflows/ci.yml](../../.github/workflows/ci.yml)，执行结果关联 GitHub 提交。

## 日常检查

项目根目录，PowerShell：

```powershell
.\.venv\Scripts\python.exe scripts/check-project-docs.py
npm run lint
npm run test:domain
npm run build

New-Item -ItemType Directory -Path .tmp -Force | Out-Null
$env:DJANGO_DB_PATH = Join-Path (Get-Location) '.tmp/verification.sqlite3'
$env:DJANGO_SECRET_KEY = 'local-isolated-verification-only'
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py test api defense_scheduler --noinput
git diff --check
```

这些环境变量用于当前测试终端，结束后关闭终端或恢复自己的配置。Django 测试框架创建独立测试数据库，禁止把测试指向真实业务库。

`npm run build` 包含 Vue／TypeScript 检查。若 npm 的 PowerShell 包装器受限制，可用 `npm.cmd`，或直接调用现有本地入口：

```powershell
node scripts/test-frontend-domain.cjs
node node_modules/eslint/bin/eslint.js . --ext .ts,.vue
node node_modules/vue-tsc/bin/vue-tsc.js -b
node node_modules/vite/bin/vite.js build
```

## CI 范围

| 检查名 | 内容 |
| --- | --- |
| `documents` | 文档本地文件与锚点引用、主入口和样例、提交空白检查 |
| `frontend` | `npm ci`、lint、领域测试、关闭 Mock／演示工具的正式构建 |
| `backend` | 固定 Python 版本系列、安装运行依赖、系统检查、迁移一致性、后端回归 |

PR、推送 `main`／`feat/**`／`fix/**`／`docs/**`／`chore/**` 和手动触发均运行。后端暂以 Windows + SQLite 为 CI 基线，前端与文档使用 Linux。工作流中的 Actions 固定到经核实的官方提交；运行版本读取根目录版本文件。

`api/tests.py` 有依赖本地 `排答辩文档/` 的可选真实资料测试，远程没有这些资料时会跳过。基础回归使用仓库内合成输入；跳过的真实资料测试不能宣称已由 CI 覆盖。浏览器、EXE、存量业务库升级和 PostgreSQL 不是本轮 PR 工作流的验证范围。

## 按风险补充验证

- 页面或跨端行为：正式构建后运行 `python scripts/test-v2-ui.py --run`，使用临时库和 Playwright。
- 迁移变化：空库和存量副本分别验证，检查关系、历史快照与回退步骤。
- 算法优化：固定输入规模和场景，验证硬约束、资源不足、耗时和软目标。
- 导出变化：检查所选版本、备注、成员计数、配色以及 Word／Excel／PDF 版式。
- 打包变化：执行 `scripts/build-exe.ps1` 后，用 `scripts/test-exe-v2.py` 核验实际 EXE；先查看脚本参数与运行前提。

仅改变文档与 CI 时执行对应检查，并对新流水线使用的现有命令做一次完整基线验证。通过后只有新改动或新失败才需要重复相应检查。

## 发布清单

1. 确认迭代范围、未实现部分、关联任务和验收结果，更新发布说明。
2. 主线 CI 通过；按本次风险执行浏览器、升级副本与导出验证。
3. 生产构建关闭 Mock 和演示工具，检查配置与打包资源。
4. 发布 EXE 时重新打包并测试实际产物，不能用源码通过替代 EXE 验证。
5. 生成校验摘要，核对压缩包不含业务库、密钥、账号文件或真实输入资料。
6. 项目协调人与相关负责人确认后创建版本标签、上传发布物，记录回退与备份方法。
7. 回填 `STATUS.md` 的版本、任务和验证链接。

验证记录至少包含日期、代码版本／PR、运行环境、命令、结果、跳过项和限制。不能把工作流存在写成远程运行通过，不能把历史验证写成当前验证。

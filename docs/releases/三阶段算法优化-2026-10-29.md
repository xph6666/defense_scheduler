# 三阶段排期算法优化与验证

日期：2026-10-29（北京时间）。本地源码更新，未提交、推送或打包 EXE；未打开浏览器，未迁移业务库。规则依据为[问题清单](../答辩系统问题清单%20%282%29.md)及用户确认的“先排组长、再排教师、最后排学生”。

## 交付变更

1. 每个阶段全局先固定所有组长和时段，再统一补齐专家与秘书，最后绑定具体学生；前两步只有任务量统计，不提前绑定学生 ID。
2. 原顺序贪心存在可复现漏排：自由度高的小组先拿走稀缺组唯一能用的专家。现按候选数优先处理稀缺组，并在必要时撤回专家／秘书选择尝试其他组合。
3. 教师搜索按时间重叠分量拆开，有节点和候选上限；优先学生覆盖，再比较完成组数，始终保护固定组长。截断时保留硬约束有效部分，未安排不表示证明无解。
4. 新增教师到场索引、占用／排序缓存、学生 ID 与导师索引；预留、释放、回溯都会使缓存失效。组长评分剪枝避免对无法改善当前选择的候选反复枚举教师。
5. 搜索上限提示经 HTTP 格式化、刷新和重验仍可见；后续补齐全部学生后不继续展示该提示。
6. README、WIKI、算法架构、业务规则、需求覆盖关系、API 和上手说明同步到 policy 3；policy 1/2 和旧 301 人证据明确保留历史适用范围。

人数仍是预／正式 3 或 5 位含组长；3 人优先 2 本院 + 1 外院，无可用外院时本院补足；5 人新增 2 位只取本院。默认任务目标 2 名学生，时间／资格为硬约束，教室后预约。算法细节和边界见[三阶段算法说明](../architecture/三阶段排期算法与优化.md)。

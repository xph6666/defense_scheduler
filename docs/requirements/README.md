# 需求管理与当前范围

当前业务基线为 [产品需求 V1.1](答辩排组排期系统_产品需求文档_V1.1.docx)，[纯需求精简版](答辩排组排期系统_纯需求精简版.docx)用于快速阅读。旧 V1 文件见[归档索引](../archive/README.md)。两份当前文件有差异时登记待确认，由业务负责人确定；实现范围不能仅凭需求文档推定。

代码已实现的能力和兼容边界见[架构升级说明](../architecture/架构升级说明.md)；高后果规则的验收入口见[业务规则与验收](业务规则与验收.md)。当前任务、负责人和优先级统一维护在 [STATUS.md](../../STATUS.md)。

## 需求变更流程

1. 描述触发条件、用户目标、范围、异常行为和可验证的验收标准。
2. 对排期、权限、导出、并发保护等重要行为分配 `REQ-` 编号；日常开发任务使用 `TASK-` 或 Issue 编号。
3. 判断受影响的规则、接口、数据迁移、界面和历史版本。
4. 业务负责人确认歧义后更新本目录的当前规则；实施任务登记到 `STATUS.md`。
5. PR 关联需求与任务，补充必要测试，验收后回填结果。

需求意图、实际实现与验证证据分别记录。有差异时保留差异说明，不能把计划中的能力写成已经完成。

## 已知缺口与待决策

以下来自 V2 架构说明的保留范围，本轮没有实现这些功能。优先级和具体负责人由团队下一次计划会议确定。

| 编号 | 问题 | 当前实现／限制 | 开发前需确认 |
| --- | --- | --- | --- |
| GAP-001 | 评分与正式答辩名单衔接 | 尚无评分、等级和预答辩结果字段 | 评分维度、录入角色、名单决定方式 |
| GAP-002 | 外院导师学生按人数集中分组 | 当前按导师、校区和容量装箱 | 少于／多于 3 人的规则；恰好 3 人的定义 |
| GAP-003 | 跨校区、外院导师整天安排 | 当前支持到场日集中与排序，可能只占半天 | 上午下午资源预留规则及失败时处理 |
| GAP-004 | 软件学院评审随机与跨版本轮换 | 当前方案内确定性按负载轮换 | 是否引入随机种子、历史累计范围 |
| GAP-005 | 并行生成与任务状态 | 当前同步生成，全局写锁内计算 | 真实容量基线、队列／取消需求和事务边界 |
| GAP-006 | PostgreSQL 与多人容量 | 配置支持数据库切换，现有主基线为 SQLite | 目标部署方式、并发人数和验证环境 |

资源不足时允许形成带错误的草稿，发布前仍需重验并阻止错误版本。启发式结果不保证全局最优；任何优化都应先维持硬约束，再明确软目标与性能验收。

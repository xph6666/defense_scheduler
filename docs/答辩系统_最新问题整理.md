# 答辩系统最新需求整理

> 本文档仅整理用户最近提出的需求，不包含此前讨论的其他排班规则。内容按“答辩规则—批次管理—前后阶段关联—数据导入”归类，供产品确认和开发实现使用。

## 一、中期答辩规则

### 1. 人数配置
- 每个中期答辩小组暂按 **5 名教师、10 名学生**配置。
- 系统应将教师人数和学生人数作为中期答辩类型的独立配置，不应直接套用其他答辩类型的人数设置。

### 2. 组长资格
- **中期答辩组长必须具有正高级职称。**
- 组长候选人筛选时应校验职称；不符合正高级职称条件的教师不得担任组长。
- 如果没有足够的正高级教师可担任组长，系统应提示无法满足条件，不得自动降低职称要求。

### 3. 生成结果与检查
- 排班结果应显示每组教师人数、学生人数、组长及其职称。
- 人数不符合配置时，应明确提示具体小组及差异原因。
- 如果最后一组不足标准人数，应明确标记并提示，不得静默补人或遗漏学生。

### 4. 待确认
- “5 名教师、10 名学生”目前按**每个小组**理解。请产品侧确认是否确实为每组人数，而非整场中期答辩的总人数。

## 二、预答辩专家构成规则

### 1. 组长资格
- **预答辩组长必须具有正高级职称。**
- 不符合正高级职称条件的教师不得进入预答辩组长候选名单。
- 如果没有符合条件的组长，系统应提示无法按规则生成，不得自动降级选择。

### 2. 本院与外院专家比例
- 预答辩小组应优先满足：**本院专家人数多于外院专家人数**。
- 在其他条件允许的情况下，尽量减少每组外院专家人数。
- 如果受可用教师或人员数量限制，无法满足上述构成，应在结果中标记并说明原因，不得静默忽略。

### 3. 数据要求
- 教师职称、所属院系及本院/外院属性应来自教师基础数据或明确的数据字段。
- 不得通过教师姓名、备注文本等方式推断职称或院内外属性。

### 4. 验收标准
- 所有预答辩小组的组长均为正高级职称。
- 系统优先生成“本院专家人数多于外院专家人数”的小组；无法满足时能够定位并说明原因。

## 三、创新与兴庆分开排班

### 1. 排班要求
- **创新和兴庆应分别排班**，不能将两个范围内的学生或答辩小组混在同一个排班批次中。
- 两个范围应分别生成排班结果，并能够分别查看、检查、调整和确认。
- 页面和导出结果中应清楚标识当前排班属于“创新”还是“兴庆”。

### 2. 冲突检查
- 虽然创新与兴庆分开生成，但如果同一位教师可能参与两个范围，系统仍需检查其跨范围的时间冲突。
- 分开排班不能导致同一教师在同一时间被安排到两个答辩小组。

### 3. 待确认
- 需要确认“创新”和“兴庆”在现有系统中对应的业务字段：是校区、答辩类别，还是两个独立的组织批次。
- 开发时应优先沿用现有系统中的真实字段和数据关系，不要仅凭名称擅自新增概念。

## 四、预答辩与正式答辩的映射关系

### 1. 需要解决的问题
- 预答辩和正式答辩是两个阶段，需要明确同一学生在两个阶段的分组关系。
- 不能简单假设预答辩小组与正式答辩小组完全相同。

### 2. 建议实现方式
- 以学生唯一标识（如学号）作为两个阶段关联的基础。
- 系统分别保存学生所属的预答辩批次/小组和正式答辩批次/小组。
- 能够从预答辩小组查看其学生在正式答辩中的去向，也能够从正式答辩小组反向查看学生原所属的预答辩小组。
- 正式答辩排班时，应能够读取已确认的预答辩学生名单，避免重复导入后丢失阶段关联。
- 正式答辩分组调整后，应同步更新学生与小组的映射关系，并保留必要的调整记录。

### 3. 映射关系应支持的情况

| 映射类型 | 说明 | 示例 |
|---|---|---|
| 一对一 | 一个预答辩小组对应一个正式答辩小组 | 预答辩第 1 组 → 正式答辩第 1 组 |
| 一对多 | 一个预答辩小组的学生拆分到多个正式答辩小组 | 预答辩第 1 组 → 正式答辩第 1、2 组 |
| 多对一 | 多个预答辩小组的学生合并到一个正式答辩小组 | 预答辩第 1、2 组 → 正式答辩第 1 组 |

不建议在业务规则尚未确认前，将映射关系写死为一对一。数据层应以学生为基础记录实际分组，界面再展示由此形成的小组对应关系。

### 4. 结果检查
- 能查看两个阶段的学生分组对应关系。
- 对尚未进入正式答辩的学生、重复关联的学生、缺失映射的学生给出明确提示。
- 分组调整后，映射展示应同步更新，避免出现旧关系。

### 5. 待确认
- 正式答辩是否必须覆盖全部预答辩学生？是否存在预答辩后不参加正式答辩的情况？
- 正式答辩分组是否允许跨预答辩小组合并，或将同一预答辩小组拆分？当前建议系统支持，最终以业务规则为准。

## 五、课表导入功能检查与调整

### 1. 需要解决的问题
- 需要检查现有课表导入功能是否能够为答辩排班提供准确的教师课程占用时间。
- 不建议在未检查现有实现前直接重做；应先确认现有导入链路是否满足排班使用，再针对缺失能力进行调整。

### 2. 检查与实现要求

| 检查项 | 具体要求 |
|---|---|
| 文件格式 | 明确支持的 Excel/CSV 格式、模板及表头；页面提供可下载模板。 |
| 必要字段 | 检查教师唯一标识、星期/日期、上课起止时间或节次、学期/周次等字段是否齐全，具体以实际课表来源为准。 |
| 教师匹配 | 优先使用教师工号等唯一标识关联系统教师，避免同名教师匹配错误。 |
| 时间解析 | 正确解析星期、节次、周次、单双周等信息，并转换为排班可使用的课程占用时段。 |
| 导入预览 | 写入前展示解析结果、匹配失败、重复记录和格式错误，供用户确认。 |
| 异常处理 | 对错误记录给出具体原因和明细；不能只提示导入失败，也不能静默丢弃异常数据。 |
| 排班读取 | 确认导入后的课程时间会被排班生成和冲突检查逻辑实际读取，而不只是保存或展示在页面上。 |
| 重复导入 | 对同一文件或相同课程记录重复导入，应有去重或更新机制，避免产生重复数据。 |

### 3. 验收标准
- 对无效文件、缺失字段、教师匹配失败、时间无法解析等情况给出明确提示。
- 导入前能够预览有效记录和异常记录。
- 导入完成后，排班检查能够识别教师的课程占用时间。
- 重复导入不会产生无法识别的重复课程数据。

## 六、开发优先级建议

| 优先级 | 需求 | 主要交付 |
|---|---|---|
| P0 | 中期答辩规则 | 每组人数配置；组长正高级职称校验；人数异常提示 |
| P0 | 预答辩专家构成 | 组长正高级职称校验；本院专家人数多于外院专家的优先规则 |
| P0 | 创新与兴庆分开排班 | 分开生成、检查、展示和确认；跨范围教师冲突检查 |
| P1 | 预答辩与正式答辩映射 | 学生级关联；支持一对一、一对多、多对一；映射检查与调整 |
| P1 | 课表导入功能 | 核查导入字段、教师匹配、时间解析、预览、异常处理及排班读取 |

## 七、需要业务方确认的事项

1. 中期答辩的“5 名教师、10 名学生”是否为**每个小组**的配置？
2. 创新和兴庆在现有系统中具体对应哪个字段或业务概念？
3. 正式答辩是否必须覆盖全部预答辩学生？是否允许学生在两个阶段之间调整小组？
4. 现有课表的数据来源、文件模板及周次/单双周规则是什么？

# 答辩系统问题清单与最终优化需求

> **文档用途：** 作为答辩排班系统后续开发、测试与验收的需求依据。  
> **当前范围：** 优先完善教师时间约束、答辩小组生成、学生分配公平性和结果展示；教室不参与当前排班计算，待时间表确定后再预约。  
> **核心原则：** 先保证排班可执行，再优化教师工作量与分组质量；不得为了追求“均衡”或“分散”而违反硬约束。

## 一、问题清单与目标

| 编号 | 模块 | 当前问题 / 风险 | 最终要求 | 优先级 |

| P02 | 学生分配完整性 | 首轮排班后可能遗留学生，系统没有明确补排或原因说明 | 所有学生必须有明确的已安排或未安排状态；首轮后自动检查剩余学生，并尝试局部补排；仍无法安排时显示名单和原因 | **P0** |

| P04 | 生成入口 | 预答辩、正式答辩使用两个独立生成入口，操作重复且容易造成规则分叉 | 只保留一个“**联合生成预答辩与正式答辩**”入口，不再分别提供两个独立生成入口 | **P1** |
| P05 | 专家人数配置 | 专家人数不便统一调整，3 人和 5 人模式的组成规则不明确 | 默认专家人数为 3，支持改为 5；页面需显示本次使用的人数配置，并按同一套规则生成 | **P1** |
| P06 | 组长安排 | 未明确先安排组长的流程，可能导致组长分配不稳定 | 先确定组长，再补齐其他专家；组长计入专家总人数，不得在补齐人数时重复计算 | **P1** |

| P08 | 5 人配置与补充专家 | 增加专家时可能把外院教师纳入补充人选，或组内人数超过配置 | 5 人模式在常规配置基础上增加 2 名专家；属于正式答辩补充专家的新增名额，只从本院教师中选择；总人数必须与配置一致 | **P1** |
| P09 | 上午、下午覆盖 | 同一教师可能上午有答辩、下午没有答辩，未充分利用其可用时间 | 若教师上午、下午均可用且仍有可安排的学生或答辩任务，应优先保证其上午、下午都有任务；确实不可行时应说明原因 | **P2** |
| P10 | 教师工作量公平性 | 教师承担的学生数量和参与答辩任务差距较大 | 综合考虑教师负责的学生数量、参与组数、可用时间和特殊备注，尽量合理分配工作量；不能只按出场次数平均 | **P2** |
| P11 | 教师任务过于分散 | 同一教师可能多次到场、每次只参与 1 名学生答辩 | 在不违反时间和分组要求的前提下，尽量把同一教师负责的学生集中安排，减少零散到场 | **P2** |
| P12 | 外院教师分散 | 同一组中可能出现多名外院教师，或外院教师集中在少数小组 | 同组原则上不安排多名外院教师，并尽可能将外院教师分散到不同组；只有在硬约束导致无可行方案时才允许例外，并应提示 | **P2** |
| P13 | 教师备注 | 个别教师允许在同一组负责多个学生，但系统可能只展示备注、不执行规则 | 支持教师备注或结构化配置，例如“允许同组安排多名该教师负责的学生”；配置必须参与算法判断 | **P2** |
| P14 | 结果排序与组号 | “生成检查”中的卡片视图和表格视图排列不一致，看起来像随机排序 | 两种视图采用相同排序：答辩日期、开始时间、稳定组标识；若组号表示时间顺序，则在最终排班后按时间统一分配展示组号 | **P1** |
| P15 | 教室预约 | 若提前将教室加入排班约束，会限制教师和时间安排 | 当前排班不考虑教室；先确定教师、学生和答辩时间，再根据最终时间表预约教室。教室字段或接口可预留，预约功能后续实现 | **P3** |

## 二、最终排班规则

### 2.1 硬约束：任何情况下都不能违反

以下规则优先于工作量均衡、上午下午覆盖以及外院教师分散等优化目标：

1. **教师可用时间必须满足。** 不得将教师安排到其明确不可用的日期或时段。
2. **教师时间不得冲突。** 同一教师不能在同一时间参加两个或多个答辩组。
3. **学生不得静默遗漏。** 每名学生最终必须显示为已安排；无法安排时，必须进入未安排清单并给出原因。
4. **专家人数不得超出配置。** 本次设置为 3 人或 5 人，就必须按对应人数校验；组长计入总人数，不得重复计数。
5. **教师资格和属性必须准确。** 本院/外院属性、教师可用时间及有效备注都必须由排班算法实际读取。
6. **教室不是当前排班约束。** 教室缺失或尚未预约，不得阻塞教师与学生的时间安排。

如硬约束之间发生冲突，系统不得通过违反教师可用时间来强行生成结果；应尽可能完成其他可行安排，并明确报告冲突及未安排对象。

### 2.2 专家小组生成

1. **先确定组长，再安排其他专家。** 组长应计入专家总人数。优先从符合资格且时间可用的教师中确定组长。
2. **默认 3 人模式。** 通常以 2 名本院教师（组长可计入其中）加 1 名外院教师为目标。若没有合适或可用的外院教师，则以本院教师补足。
3. **5 人模式。** 在统一生成入口中将专家人数调整为 5。对于正式答辩增加的补充专家名额，只能从本院教师中选择；新增人数不得造成组内总人数超过 5 人。
4. **外院教师尽量分散。** 同一组原则上只安排 1 名外院教师，并尽量分配到不同小组。若受教师时间、人员数量或资格限制而无法满足，应优先满足硬约束，并记录原因。
5. **不单独生成预答辩或正式答辩。** 页面只保留“联合生成预答辩与正式答辩”一个入口，通过专家人数配置适配 3 人或 5 人安排。

> 说明：默认 3 人模式下的“2 名本院教师 + 1 名外院教师”是优先目标，不是允许违反教师时间约束的硬条件。无合适外院教师时，可用本院教师补足。

### 2.3 学生分组与教师任务集中

1. 以**每组原则上安排 2 名学生**作为默认分组目标；对同一教师负责的学生，也尽量按每次 2 名学生的任务单元集中安排。
2. 对同一教师负责的学生，尽量集中安排，减少同一教师多次到场且每次只参与 1 名学生答辩的情况。
3. 允许为个别教师设置“同组可以安排多名其负责学生”等备注或结构化选项，并在满足时间约束的情况下优先合并安排。
4. 不应为了凑足每组 2 名学生而违反教师时间约束或学生已有安排。若剩余学生无法与其他学生合组，可安排到可行的小组或时段，并在结果中标明实际人数。
5. 首轮生成后应检查剩余学生，并尝试局部补排。例如某教师有 5 名学生，上午先安排 2 名、下午安排 2 名，剩余 1 名学生可在教师时间允许、专家条件满足的空余时段增补。
6. 增补时应尽量保留已满足硬约束的结果，只调整必要的局部安排；如果仍不可行，应给出具体原因，不得静默丢弃学生。

### 2.4 上午、下午覆盖

1. 对上午、下午均可用的教师，若上午已安排该教师参加答辩，且下午仍有可安排的负责学生或任务，应优先为其安排下午任务。
2. 若教师本人下午不可用，则不要求下午覆盖。
3. 若教师两个时段都可用，但由于学生数量、分组容量、其他教师时间冲突或专家组成限制而无法安排两个时段，系统应将其列为软目标未满足，并说明原因。
4. 上午、下午覆盖属于**软优化目标**，不能凌驾于教师时间硬约束、专家资格和学生分配完整性之上。

### 2.5 教师工作量公平性

不以“每位教师出场次数相同”为唯一目标，而应综合考虑：

- 教师负责或参与答辩的学生数量；
- 教师参与的答辩组数及到场次数；
- 教师可用的日期和时段；
- 教师关于同组安排多名学生的有效备注。

在可用时间和其他条件相近时，尽量让负责学生数量相近的教师承担相近的任务量，并优先减少不必要的重复到场与零散安排。对由于可用时间或人员资格造成的工作量差异，系统应保留统计结果，不能为追求表面均衡而制造时间冲突。

## 三、界面与结果展示要求

### 3.1 统一生成入口

- 只保留一个入口，名称为：**联合生成预答辩与正式答辩**。
- 不再分别保留预答辩和正式答辩的独立生成入口。
- 专家人数默认为 3，并支持调整为 5。
- 页面明确展示本次使用的专家人数、排班日期范围及生成结果状态。

### 3.2 “生成检查”卡片视图和表格视图

- 卡片视图与表格视图使用同一排序规则和同一份排班数据。
- 排序优先级：**答辩日期 → 开始时间 → 稳定组标识**。
- 如果组号表示实际时间顺序，应在最终排班确认后按时间统一分配展示组号。
- 如果组号是不可变的内部业务标识，不应为排序而修改内部标识，应单独生成展示序号。
- 切换卡片和表格视图后，答辩顺序必须保持一致。

### 3.3 教师信息与备注

- 教师本院/外院属性必须以可信数据字段为准，不能仅根据姓名进行推断。
- 对“王飞（软）”与“王飞”进行数据修正和回归检查。
- 支持查看和维护教师可用时间、院系属性及特殊备注。
- 备注必须参与排班判断；无效或无法识别的备注应提示用户确认，不能仅显示在页面上。

### 3.4 教室预约（后续步骤）

- 当前阶段不把教室可用性、容量或教室冲突作为排班算法约束。
- 系统先依据教师可用时间、学生任务和专家组成规则生成时间表。
- **排班完成后，再根据已确定的日期和时段预约教室。**
- 可以预留教室字段、展示位置或预约接口，但不应要求当前排班依赖教室信息。

## 四、开发优先级

### P0：排班可执行性与完整性

- [ ] 教师可用时间作为硬约束，禁止安排到不可用时段。
- [ ] 检查同一教师同一时段参加多个答辩组的冲突。
- [ ] 检查所有学生是否已安排；未安排学生必须有明确清单和原因。
- [ ] 当前排班不使用教室作为约束。

### P1：关键功能与结果正确性

- [ ] 修正“王飞（软）”与“王飞”的本院/外院属性。
- [ ] 合并为“联合生成预答辩与正式答辩”一个入口。
- [ ] 专家人数默认 3，支持配置为 5。
- [ ] 明确组长先排且计入专家总人数。
- [ ] 落实 3 人、5 人模式下的专家组成规则，以及正式答辩补充专家仅从本院教师中选择的规则。
- [ ] 卡片视图、表格视图按同一时间规则排序。

### P2：排班质量优化

- [ ] 尽量满足上午、下午都有任务的要求。
- [ ] 按学生数量和可用时间合理平衡教师工作量。
- [ ] 尽量集中同一教师负责的学生，减少每次只参与 1 名学生的零散安排。
- [ ] 尽量分散外院教师，避免同组出现多名外院教师。
- [ ] 支持教师特殊备注并让备注真正影响算法。
- [ ] 对剩余学生尝试局部补排，尽量不推翻已可行的排班。

### P3：教室预约与后续扩展

- [ ] 排班完成后，根据最终确定的日期和时段预约教室。
- [ ] 当前可预留教室字段或接口，但不要求完成教室自动分配。

| A10 | 工作量与任务集中度 | 能统计每位教师负责的学生数、参与组数和任务分布；同组多学生的有效备注能够影响排班 |
| A11 | 剩余学生补排 | 首轮排班后如仍有学生未安排，系统会尝试局部补排；仍失败时显示名单和具体原因 |
| A12 | 外院教师分布 | 可行方案存在时，同组原则上不出现多名外院教师，且外院教师尽量分散到不同组 |
| A13 | 视图排序 | 卡片视图和表格视图按答辩日期、开始时间及稳定组标识排序，切换视图后顺序一致 |
| A14 | 教室预约流程 | 当前排班不依赖教室信息；时间表确定后才进入教室预约流程 |

## 六、异常情况处理

- **教师未维护可用时间：** 标记为待确认，不应默认视为所有时段均可用；必要时提示补全信息。
- **外院教师不足或时间不匹配：** 在满足教师时间和专家人数约束的前提下使用本院教师补足，并提示未满足外院教师分散目标的原因。
- **某教师的学生无法按默认人数成组：** 允许在可行时段局部增补；必要时形成单人小组或其他例外安排，并在结果中标明，不得因此遗漏学生。
- **上午、下午覆盖不可实现：** 保留硬约束优先原则，并记录无法满足该软目标的原因。
- **组号与时间顺序不一致：** 区分内部标识和展示序号；不得为排序而错误修改数据库主键或关联关系。
- **教师备注存在歧义：** 提示用户确认，不得将无法识别的备注静默忽略。
- **教室尚未预约或预约冲突：** 不影响当前人员和时间排班；在后续教室预约阶段单独处理。

## 七、实现原则总结

1. **先保证可执行：** 教师时间、教师冲突和学生分配完整性优先。
2. **再满足基本组成：** 先排组长，默认 3 人，支持 5 人；组长计入专家总人数。
3. **再优化排班质量：** 尽量公平分配教师工作量、集中同一教师负责的学生、覆盖上午和下午，并分散外院教师。
4. **结果必须可解释：** 未安排学生、未满足的软目标以及冲突原因都应显示出来。
5. **教室最后处理：** 先生成教师和学生的时间表，再根据该时间表预约教室。
